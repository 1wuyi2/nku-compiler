\begin{abstract}

本实验围绕编译器从高级语言源程序到目标程序的处理过程展开。首先以循环实现的阶乘 C 程序为例，利用 GCC 和 Clang/LLVM 观察预处理、词法分析、抽象语法树、LLVM IR、汇编、目标文件和链接等阶段的输出，并比较不同优化级别对生成代码的影响。在此基础上，设计了一段覆盖常量、数组、算术运算、条件分支、循环、函数调用和运行时输入输出的 SysY 程序，分别进行 LLVM IR 和 RISC-V 目标表示实现。RISC-V 部分进一步与 SysY 运行时库进行静态链接，并通过 QEMU 对普通输入和边界输入进行验证。进阶部分结合 AscendNPU IR 的 VecAdd 示例，对 MLIR 多层 Dialect 与渐进式 lowering 的基本思想进行了文档调研和分析。通过上述实验，加深了对编译器前端、中间表示、目标代码和运行时环境之间关系的理解。

\end{abstract}

\noindent

\section{引言}
% =========================================================

编译系统的作用并不仅是将高级语言源程序一次性转换为机器代码，
而是通过预处理、词法分析、语法分析、语义分析、中间代码生成与优化、
目标代码生成、汇编和链接等多个阶段，逐步降低程序的抽象层次，
最终形成能够在目标平台运行的可执行程序。

LLVM 将中间表示设计为相对独立于源语言和目标体系结构的 LLVM IR，
使前端分析、通用优化与后端代码生成能够相对解耦。
另一方面，面向 AI 加速器的编译系统还需要表达张量操作、
专用存储层次、数据搬运以及硬件计算单元等信息，
因此 MLIR 进一步采用多层中间表示和 Dialect 机制，
允许程序在不同抽象层次之间逐级 lowering。

本实验首先以一个简单 C 程序为例，实际观察 GCC 和 Clang/LLVM
语言处理系统从源程序到可执行文件的完整过程，并研究不同编译阶段
输出与源程序之间的关系。在此基础上，两位成员共同设计统一的
SysY 测试程序和测试用例，随后分别完成 LLVM IR 与 RISC-V 汇编
两种等价低层实现，并通过 SysY 运行时库和实际执行验证其正确性。

此外，为进一步理解现代 AI 编译器中端的设计思想，本实验结合
AscendNPU IR 官方 VecAdd 示例，对 MLIR 的多级 Dialect、
存储空间表达和逐层 lowering 过程进行文档调研与分析。

\subsection{实验任务}

本次预备工作围绕“了解编译器”展开，目标并不是只完成一次程序编译，而是通过实际工具观察高级语言程序在编译过程中经历的不同表示形式，并理解这些表示之间的关系。

基础部分首先选择一个规模适中的 C 程序，利用 GCC 和 Clang/LLVM 提供的命令行选项，依次观察预处理结果、词法单元、抽象语法树、LLVM IR、汇编程序、目标文件和最终可执行文件。通过这些中间产物，可以将课堂中的编译流程具体落实到实际文件和指令中。

在此基础上，进一步设计具有代表性的 SysY 程序，使其覆盖数值运算、赋值、条件分支、循环、函数调用以及数组等语言结构，并分别手工实现等价 LLVM IR 和 RISC-V 汇编代码。实现后与课程提供的 SysY 运行时库进行链接，通过实际执行验证不同低层表示是否保持与源程序一致的语义。

进阶部分结合 AscendNPU IR 的 VecAdd 示例，对 MLIR 的 Dialect、多层中间表示以及渐进式 lowering 思想进行调研，从而将实验范围由传统通用编译器扩展到面向 AI 加速器的编译流程。

实验主要在 Windows + WSL2 Ubuntu 环境下完成。第一部分使用 GCC 13.3.0 和 LLVM 18；RISC-V 部分使用 GCC 15.1.0、GNU Binutils 2.45 和 qemu-riscv64 8.2.2。

\section{C 程序编译流程观察}
% =========================================================

\subsection{实验程序与总体流程}

实验选取循环实现的阶乘程序作为贯穿各阶段的示例。程序定义 \texttt{factorial(int n)} 函数，通过循环不断更新累乘结果，主函数读取整数后调用该函数并输出结果。该程序虽然规模较小，但同时包含函数定义、局部变量、循环、整数运算以及标准库函数调用，能够较完整地观察编译过程中不同阶段的变化。

输入 5 时程序输出 120，说明后续观察到的各类中间结果均对应一个功能正确的源程序。

\begin{figure}[H]
\centering
\includegraphics[width=0.76\textwidth]
{images/part1/part1_source_run.png}
\caption{阶乘程序运行结果}
\label{fig:source-run}
\end{figure}

整个处理过程可以概括为：

\[
\text{main.c}
\rightarrow
\text{main.i}
\rightarrow
\text{Token / AST}
\rightarrow
\text{LLVM IR}
\rightarrow
\text{Assembly}
\rightarrow
\text{Object}
\rightarrow
\text{Executable}.
\]

这些阶段并不是简单的文件格式变化，而是在不断降低程序的抽象层次。源程序强调程序员能够理解的语义结构，AST 强调语法关系，LLVM IR 开始显式体现基本块和数据访问，汇编程序则已经直接面向具体目标体系结构。

\subsection{预处理、词法与语法结构}

首先使用 GCC 的预处理选项：

\begin{lstlisting}
gcc -E main.c -o main.i
\end{lstlisting}

源文件 \texttt{main.c} 只有 33 行，而生成的 \texttt{main.i} 达到 847 行。主要原因是 \texttt{stdio.h} 等标准头文件中的声明被展开，同时源程序中定义的宏 \texttt{START\_VALUE} 已经被替换为常量 1。

\begin{figure}[H]
\centering
\includegraphics[width=0.72\textwidth]
{images/part1/part1_preprocess.png}
\caption{预处理前后的文件规模及宏展开结果}
\label{fig:preprocess}
\end{figure}

因此，预处理阶段仍属于源语言层面的处理。它不会直接生成机器代码，而是完成宏替换、头文件展开等工作，为后续真正的编译阶段准备完整输入。

进一步使用 Clang 输出 Token 和 AST。Token 输出中可以看到 \texttt{int}、\texttt{while} 等关键字，\texttt{factorial}、\texttt{result} 等标识符，以及括号、运算符和数值常量。AST 则进一步将这些线性的词法单元组织为树形语法结构。例如，\texttt{factorial} 对应 \texttt{FunctionDecl} 节点，循环对应 \texttt{WhileStmt}，表达式中的乘法和加法则对应 \texttt{BinaryOperator}。

\subsection{优化前后的代码差异}

实验还分别生成了 \texttt{-O0} 与 \texttt{-O2} 版本的汇编代码。未优化情况下，\texttt{i} 和 \texttt{result} 等局部变量频繁通过栈访问，控制流也基本保持源程序的形式。

例如 \texttt{-O0} 中循环主体包含：

\begin{lstlisting}
movl    -4(%rbp), %eax
imull   -8(%rbp), %eax
movl    %eax, -4(%rbp)
addl    $1, -8(%rbp)
\end{lstlisting}

而 \texttt{-O2} 中对应循环被重新组织为：

\begin{lstlisting}
imull   %eax, %edx
leal    1(%rax), %ecx
addl    $2, %eax
imull   %ecx, %edx
\end{lstlisting}

可以看到优化后更多中间值直接保存在寄存器中，而且一次循环可以完成两个相邻乘数的累乘，减少循环控制次数。

此外，\texttt{-O2} 版本的 \texttt{main} 中原有的 \texttt{call factorial} 消失，阶乘计算逻辑被直接展开到调用位置，体现出函数内联优化。

因此，编译器优化的本质并不是简单缩短汇编文件，而是在保证程序外部可观察语义不变的前提下重新组织数据流、控制流和函数调用，从而降低访存、分支和调用等开销。

\section{SysY 测试程序设计}
% =========================================================

\subsection{程序功能与设计思路}

第二部分实验需要分别手工实现 LLVM IR 和 RISC-V 汇编。
为了使两种低层表示能够建立在同一语义基准上，本实验首先共同设计了一段规模适中、同时包含多种 SysY 语言结构的测试程序。

程序由 \texttt{main} 和 \texttt{calc} 两个函数组成。
其中，\texttt{main} 负责读取输入、执行上下界检查、调用计算函数并完成最终结果输出；
\texttt{calc} 则负责主要循环计算过程。

主函数首先通过

\begin{lstlisting}
n = getint();
\end{lstlisting}

读取一个整数。
为了保证后续访问

\begin{lstlisting}
int values[8];
\end{lstlisting}

时不会发生数组越界，程序将输入限制在区间 $[1,8]$：

\begin{lstlisting}
if (n < 1)
{
    n = 1;
}
else
{
    if (n > LIMIT)
    {
        n = LIMIT;
    }
}
\end{lstlisting}

其中常量

\begin{lstlisting}
const int LIMIT = 8;
\end{lstlisting}

与数组长度保持一致。

完成输入修正后，主函数调用

\begin{lstlisting}
result = calc(n);
\end{lstlisting}

得到主要计算结果，并继续执行整数除法和取模：

\begin{lstlisting}
quotient = n / 2;
remainder = n % 2;
\end{lstlisting}

最后将 \texttt{calc} 的返回值、商、余数以及常量
\texttt{BASE=3} 相加，并通过 \texttt{putint} 和
\texttt{putch} 输出结果。

因此，该程序既包含较典型的数值计算，又能够覆盖数组、循环、条件分支、函数调用和运行时接口等后续低层实现中需要重点处理的结构。


\subsection{核心计算过程与语言特性覆盖}

\texttt{calc} 函数是程序的核心计算部分。
函数内部定义长度为 8 的整型数组：

\begin{lstlisting}
int values[8];
\end{lstlisting}

并使用循环依次计算数组前 $n$ 个元素：

\begin{lstlisting}
while (i < n)
{
    if ((i + 1) % 2 == 0)
    {
        values[i] = (i + 1) * (i + 1);
    }
    else
    {
        values[i] = -(i + 1);
    }

    result = result + values[i];
    i = i + 1;
}
\end{lstlisting}

当 $i+1$ 为偶数时，将其平方写入数组；
当 $i+1$ 为奇数时，则将其相反数写入数组。
每次完成数组赋值后，将当前元素累加到 \texttt{result} 中。

例如，当

\[
n=5
\]

时，数组前五项依次为

\[
[-1,\ 4,\ -3,\ 16,\ -5].
\]

因此：

\[
\texttt{calc}(5)
=
-1+4-3+16-5
=
11.
\]

主函数继续计算：

\[
5/2=2,
\qquad
5\bmod 2=1,
\]

并加入：

\[
\texttt{BASE}=3,
\]

所以最终得到：

\[
11+2+1+3=17.
\]

这一计算过程既可以人工验证，也可以作为后续 LLVM IR 和 RISC-V 两种实现的语义检查基准。

\section{LLVM IR 实现与验证}
% =========================================================

\subsection{总体结构与基本块设计}

\noindent
\textbf{主要负责人：王帅（2413995）}

LLVM IR 部分以第 3 章中的 SysY 程序作为语义基准，
手工完成 \texttt{calc} 和 \texttt{main} 两个函数的中间表示。

实现采用接近未优化编译结果的直接翻译方式：
局部变量首先使用 \texttt{alloca} 在函数栈帧中分配空间，
随后通过 \texttt{load} 和 \texttt{store} 完成读写。

与 SysY 中按照语句顺序组织程序不同，LLVM IR 中控制流以基本块为单位组织。
每个基本块以标签开始，并以 \texttt{br} 或 \texttt{ret} 等终结指令结束。

以 \texttt{calc} 为例，主要基本块包括：

\begin{table}[H]
\centering
\caption{\texttt{calc} 函数基本块及作用}
\begin{tabularx}{\textwidth}{@{}p{3.0cm}X@{}}
\toprule
基本块 & 主要作用 \\
\midrule

\texttt{entry} &
分配局部变量并完成初值设置 \\

\texttt{loop.cond} &
读取 $i$ 和 $n$，判断是否继续执行循环 \\

\texttt{loop.body} &
计算 $i+1$、奇偶性和数组元素地址 \\

\texttt{if.then} &
处理偶数情况，将平方写入数组 \\

\texttt{if.else} &
处理奇数情况，将负值写入数组 \\

\texttt{if.end} &
读取数组元素、更新累加结果和循环变量 \\

\texttt{loop.end} &
读取最终结果并返回 \\

\bottomrule
\end{tabularx}
\end{table}

因此，源程序中的结构化控制语句，在 LLVM IR 中被显式转换为多个基本块之间的有向控制流。


\subsection{局部变量与数组寻址}

SysY 中的局部整型变量统一使用 LLVM IR 的 \texttt{i32} 类型。

在 \texttt{calc} 函数入口处，首先为局部对象分配空间：

\begin{lstlisting}
%values = alloca [8 x i32], align 16
%i = alloca i32, align 4
%result = alloca i32, align 4
%n = alloca i32, align 4
\end{lstlisting}

其中：

\begin{itemize}
    \item \texttt{values} 对应 SysY 中的 \texttt{int values[8]}；
    \item \texttt{i} 对应循环变量；
    \item \texttt{result} 保存累加结果；
    \item \texttt{n} 保存传入的函数参数。
\end{itemize}

参数 \texttt{\%n\_arg} 进入函数后，通过：

\begin{lstlisting}
store i32 %n_arg, i32* %n, align 4
\end{lstlisting}

写入局部存储空间。

之后需要使用该变量时，再通过：

\begin{lstlisting}
%n_val = load i32, i32* %n, align 4
\end{lstlisting}

取得实际值。

数组元素

\[
\texttt{values}[i]
\]

不能像高级语言一样直接使用下标访问，而需要显式计算元素地址。

首先将 32 位索引转换为 64 位：

\begin{lstlisting}
%idx64 = sext i32 %i_cur to i64
\end{lstlisting}

然后使用 \texttt{getelementptr}：

\begin{lstlisting}
%elem_ptr = getelementptr inbounds [8 x i32],
            [8 x i32]* %values,
            i64 0,
            i64 %idx64
\end{lstlisting}

这里第一个索引 0 表示仍然以当前数组对象为基础，
第二个索引 \texttt{\%idx64} 选择数组中的第 $i$ 个元素。

因此，SysY 中一次简单的数组下标访问，在 LLVM IR 中被明确拆分为索引类型转换和地址计算。


\subsection{控制流与整数运算}

SysY 中的：

\begin{lstlisting}
while (i < n)
\end{lstlisting}

在 LLVM IR 中由条件比较和基本块跳转实现。

循环条件部分为：

\begin{lstlisting}
%i_val = load i32, i32* %i, align 4
%n_val = load i32, i32* %n, align 4
%loop_cmp = icmp slt i32 %i_val, %n_val
br i1 %loop_cmp, label %loop.body, label %loop.end
\end{lstlisting}

其中 \texttt{icmp slt} 执行有符号整数“小于”比较。

如果比较结果为真，则进入：

\begin{lstlisting}
loop.body
\end{lstlisting}

否则跳转到：

\begin{lstlisting}
loop.end
\end{lstlisting}

结束循环。

循环内部的奇偶判断：

\begin{lstlisting}
if ((i + 1) % 2 == 0)
\end{lstlisting}

转换为：

\begin{lstlisting}
%i_plus_1 = add nsw i32 %i_cur, 1
%mod2 = srem i32 %i_plus_1, 2
%is_even = icmp eq i32 %mod2, 0
br i1 %is_even, label %if.then, label %if.else
\end{lstlisting}

其中：

\begin{itemize}
    \item \texttt{add} 对应整数加法；
    \item \texttt{srem} 对应有符号整数取模；
    \item \texttt{icmp eq} 判断余数是否等于 0；
    \item \texttt{br} 根据比较结果选择不同基本块。
\end{itemize}

偶数分支中的平方运算：

\begin{lstlisting}
%square = mul nsw i32 %i_plus_1, %i_plus_1
\end{lstlisting}

使用 \texttt{mul} 实现。

奇数分支中的一元负号：

\begin{lstlisting}
%negative = sub nsw i32 0, %i_plus_1
\end{lstlisting}

通过 $0-x$ 转换为减法实现。

主函数中的整数除法与取模分别使用：

\begin{lstlisting}
%q = sdiv i32 %n2, 2
%r = srem i32 %n2, 2
\end{lstlisting}

因此，SysY 中的基本算术运算均可以映射到对应的 LLVM IR 整数指令。

\subsection{函数调用与 SysY 运行时接口}

SysY 程序依赖课程运行时提供输入输出函数。

在 LLVM IR 中首先声明：

\begin{lstlisting}
declare i32 @getint()
declare void @putint(i32)
declare void @putch(i32)
\end{lstlisting}

这些声明只给出函数类型，并没有在当前 \texttt{main.ll} 中定义函数体。
具体实现将在链接阶段由 SysY 运行时库提供。

读取输入时使用：

\begin{lstlisting}
%input = call i32 @getint()
\end{lstlisting}

返回值直接作为 SSA 值保存在 \texttt{\%input} 中。

用户自定义函数调用：

\begin{lstlisting}
%calc_result = call i32 @calc(i32 %n2)
\end{lstlisting}

表示将 \texttt{\%n2} 作为参数传入 \texttt{calc}，
并取得一个 \texttt{i32} 返回值。

最终输出使用：

\begin{lstlisting}
call void @putint(i32 %sum3)
call void @putch(i32 10)
\end{lstlisting}

其中 \texttt{putch(10)} 输出换行字符。

与后续 RISC-V 汇编实现相比，LLVM IR 的函数调用仍然保留了较高层的函数和参数类型信息。
此时无需显式指定参数寄存器或保存返回地址，这些更接近目标体系结构的细节由后端代码生成阶段继续处理。

\subsection{栈帧与数组寻址}

\texttt{calc} 函数包含 \texttt{values[8]}、\texttt{i}、\texttt{result} 以及参数 \texttt{n}。一个 SysY \texttt{int} 占 4 字节，因此数组本身需要 32 字节。实现中统一为该函数分配 48 字节栈帧。

\begin{table}[H]
\centering
\caption{\texttt{calc} 函数主要栈空间布局}
\begin{tabular}{ll}
\toprule
位置 & 内容 \\
\midrule
\texttt{0(sp)--28(sp)} & \texttt{values[0]--values[7]} \\
\texttt{32(sp)} & \texttt{i} \\
\texttt{36(sp)} & \texttt{result} \\
\texttt{40(sp)} & 参数 \texttt{n} \\
\bottomrule
\end{tabular}
\end{table}

48 字节本身是 16 的整数倍，因此调用过程中能够保持栈对齐。

对于数组元素

\[
\texttt{values}[i],
\]

由于每个元素宽度为 4 字节，因此其地址满足：

\[
\mathrm{addr}(\texttt{values}[i])
=
\mathrm{sp}+4i.
\]

汇编中可以先通过左移两位得到 $4i$：

\[
i \ll 2 = 4i,
\]

再与 \texttt{sp} 相加得到数组元素地址。

这个过程体现出高级语言中的数组下标访问，在机器层实际上需要转换为“基地址 + 偏移量”的地址计算。

\subsection{控制流与整数运算}

源程序中的：

\[
\texttt{while}(i<n)
\]

在汇编中不再存在一个独立的“循环”指令，而是转换为比较和跳转。

每轮循环开始时先比较 $i$ 与 $n$。如果

\[
i\ge n,
\]

则跳转到循环结束标签；否则继续执行循环体。循环体结束后再无条件跳回条件判断位置。

同样，源程序中的：

\[
(i+1)\bmod2==0
\]

使用 \texttt{remw} 计算余数，再根据结果是否为 0 跳转到不同分支。因此，从目标代码角度看，\texttt{while}、\texttt{if} 和 \texttt{else} 最终都可以归结为基本块之间的控制流转移。

虽然目标体系结构为 RV64，但 SysY 中的 \texttt{int} 为 32 位整数。因此本程序主要使用：

\begin{center}
\texttt{addw}、
\texttt{addiw}、
\texttt{subw}、
\texttt{mulw}、
\texttt{divw}、
\texttt{remw}
\end{center}

等 32 位整数运算指令，使目标代码的整数语义与 SysY 保持一致。

\subsection{函数调用与运行时库}

RISC-V 调用约定规定整数参数和返回值优先通过 \texttt{a0--a7} 等参数寄存器进行传递。

本程序调用：

\[
\texttt{calc}(n)
\]

之前，首先将参数 $n$ 放入 \texttt{a0}；函数结束后，返回结果同样通过 \texttt{a0} 返回。

\texttt{main} 还需要调用：

\[
\texttt{getint},
\qquad
\texttt{putint},
\qquad
\texttt{putch}.
\]

这些函数由 SysY 运行时库提供。

由于执行 \texttt{call} 会覆盖返回地址寄存器 \texttt{ra}，因此 \texttt{main} 在函数入口处先将 \texttt{ra} 保存到栈中，结束前再恢复。

这一实现说明，高级语言中的一次函数调用，在目标代码层面实际上还需要处理参数位置、返回值、返回地址和栈空间恢复等问题。

\section{进阶探索：MLIR 与 AscendNPU IR}
% =========================================================

\subsection{从 LLVM IR 到多层中间表示}

基础实验中的 LLVM IR 提供了一种较统一的中间表示。C 程序被转换为 \texttt{alloca}、\texttt{load}、\texttt{store}、\texttt{icmp}、\texttt{br} 等较低层操作之后，源语言中的大部分高级结构已经被消除。这种设计有利于为不同前端和不同目标机器建立统一接口。

但面向 AI 加速器时，程序通常还包含张量、向量运算、专用存储空间和数据搬运等更丰富的语义。如果过早全部下降到统一低层指令，这些信息可能难以继续用于针对硬件特点的优化。

MLIR，即 Multi-Level Intermediate Representation，采用多层中间表示思想，通过 Dialect 描述不同抽象层次的操作。编译过程可以先保留较高层领域语义，再经过多个 Pass 逐步下降：

\[
\text{High-level IR}
\rightarrow
\text{Domain Dialect}
\rightarrow
\text{Hardware Dialect}
\rightarrow
\text{Low-level IR}.
\]

因此，lowering 不再只是“一次从高级语言变成低层 IR”，而可以理解为多个中间表示之间连续降低抽象层次的过程。

\subsection{AscendNPU IR 官方 VecAdd 示例分析}

根据 AscendNPU IR 官方快速入门中的 VecAdd 示例，
其输入和输出均使用带有显式存储空间属性的 \texttt{memref} 表示。
例如，全局内存中的数据使用：

\begin{lstlisting}
memref<16xi16, #hivm.address_space<gm>>
\end{lstlisting}

而片上 Unified Buffer 中的临时数据使用：

\begin{lstlisting}
memref<16xi16, #hivm.address_space<ub>>
\end{lstlisting}

这与普通 LLVM IR 中相对通用的内存指针存在明显区别：
AscendNPU IR 在中间表示阶段已经显式保留了数据所在的硬件存储层次。

官方 VecAdd 的主要计算过程可以抽象为：

\[
\mathrm{GM}
\overset{\texttt{hivm.hir.load}}{\longrightarrow}
\mathrm{UB}
\overset{\texttt{hivm.hir.vadd}}{\longrightarrow}
\mathrm{UB}
\overset{\texttt{hivm.hir.store}}{\longrightarrow}
\mathrm{GM}.
\]

其中，两路输入首先分别从 GM 搬运到 UB：

\begin{lstlisting}
hivm.hir.load ...
\end{lstlisting}

随后在 UB 上执行向量加法：

\begin{lstlisting}
hivm.hir.vadd ...
\end{lstlisting}

最后将结果重新写回 GM：

\begin{lstlisting}
hivm.hir.store ...
\end{lstlisting}

因此，虽然源语义只是简单的

\[
C=A+B,
\]

但面向 NPU 的中间表示还需要显式表达数据位于何处、
数据如何移动以及使用何种硬件操作完成计算。

官方示例使用如下命令进行编译：

\begin{lstlisting}
bishengir-compile add.mlir -enable-hivm-compile -o kernel.o
\end{lstlisting}

最终生成可以在昇腾 NPU 上执行的设备侧算子二进制
\texttt{kernel.o}。

由于本实验环境没有配置 CANN 以及昇腾 NPU 设备，
因此没有将该示例的上板执行结果作为本机实验结果，
而是按照题目允许的方式，通过官方文档和 IR 示例对其中端表示进行分析。

\subsection{多级 IR 与逐层 Lowering}

AscendNPU IR 建立在 MLIR 基础上。
与 LLVM IR 主要围绕一种核心中间表示展开不同，
MLIR 允许不同 Dialect 在多个抽象层次上共存，
使编译器能够在仍然保留高层语义时进行领域相关优化，
再逐步降低到接近硬件的表示。

从 AscendNPU IR 的整体接口设计可以将这种过程理解为：

\[
\text{Torch IR}
\rightarrow
\text{Linalg / HFusion IR}
\rightarrow
\text{HIVM IR}
\rightarrow
\text{NPU Device Binary}.
\]

较高层 IR 主要描述框架算子和张量计算语义；
Linalg/HFusion 层可以进一步进行融合、tiling 和调度；
HIVM IR 则更加接近昇腾硬件，
能够显式表示 GM、UB 等存储空间以及向量计算和数据搬运操作。

需要说明的是，官方快速入门中的 VecAdd 示例已经直接给出了
较接近硬件层的 HIVM MLIR，因此示例本身并没有完整展示
从 Torch IR 开始的每一个转换步骤。
本实验结合官方的多级 IR 文档理解其整体 lowering 思路，
而不将文档中未实际展示的中间 Pass 输出作为本机实验结果。

这一设计说明，多级 lowering 的意义并不只是把一种文本格式
连续改写为另一种文本格式，而是在不同阶段有选择地保留适合当前
优化任务的语义信息。较高层阶段保留张量和算子结构，
较低层阶段则逐渐显式化存储层次、数据搬运和硬件指令。

\section{总结}
% =========================================================

本实验围绕编译器从高级语言到目标程序的完整处理过程展开。第一部分通过 GCC 和 Clang/LLVM 的实际输出观察了预处理、词法分析、AST、LLVM IR、汇编、目标文件和链接等阶段，使课堂中较为抽象的编译流程与实际文件和指令建立了对应关系。

对 \texttt{-O0} 与 \texttt{-O2} 汇编代码的比较还表明，编译优化会重新组织寄存器使用、循环结构甚至函数调用方式，而不是简单地对源程序进行逐句翻译。优化的目标是在保持程序语义一致的前提下减少不必要的访存、分支和函数调用等开销。

第二部分首先共同设计统一的 SysY 测试程序和测试用例，并在此基础上分别完成 LLVM IR 与 RISC-V 两种低层表示。LLVM IR 部分涉及基本块划分、局部变量与数组表示、\texttt{getelementptr} 地址计算、条件和循环控制流、运行时函数声明及链接；RISC-V 部分进一步涉及局部变量的栈上布局、数组的基址加偏移寻址、RV64 环境中的 32 位整数运算以及函数调用约定。两种实现均使用 0、1、4、5、8、10 六组输入验证，并得到与 SysY 源程序一致的结果。
进阶部分进一步将对中间表示的认识从 LLVM IR 扩展到
MLIR 与 AscendNPU IR。通过分析官方 VecAdd 示例可以看到，
面向 NPU 等专用硬件时，中间表示不仅需要描述“执行什么计算”，
还需要显式表达数据所在的存储空间、数据搬运过程以及相应的
硬件计算操作。MLIR 通过 Dialect 和逐层 lowering，
使编译器能够在不同抽象层次保留适合当前优化阶段的信息，
最终逐步降低为面向目标硬件的低层表示。

通过本次实验，可以更加具体地认识到，
编译器并不是简单的“源代码到机器码”转换工具，
而是由前端分析、中间表示、优化、目标代码生成、
汇编、链接以及运行时支持共同构成的完整系统。
